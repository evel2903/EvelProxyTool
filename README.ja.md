<h1 align="center">EvelProxyTool</h1>

<p align="center">
  One Proxy. All Models. Any Platform.<br>
  CLIProxyAPI のポータブルデスクトップコンソール —— 私たちの目標は、トークンを free（無料ではなく、自由という意味）にすることです。
</p>

## 概要

EvelProxyTool は、[CLIProxyAPI](https://github.com/router-for-me/CLIProxyAPI) を基盤としたグラフィカルな
デスクトップ管理ツールです。コアのライフサイクル管理、OAuth 認可、API プロバイダーの集約、プロトコル変換、
認証情報管理、クォータ確認、利用履歴、モデルエイリアス、エージェントクライアント設定を 1 つの画面に
まとめており、1 つのローカルプロキシで Claude・Codex・Gemini や、それらの API に対応するあらゆる
エージェント/CLI ツールをまとめて扱えます。

アプリケーションは Tauri、React、Rust で構築されており、対応する CLIProxyAPI コアのアーカイブを同梱できるため、
初回セットアップやオフラインインストールが簡単になります。

## 機能紹介

### ホームダッシュボードとローカル API エンドポイント

ホームページでは、ローカルプロキシの実行状況とすぐに使える API エンドポイントを一目で確認できます。

- CLIProxyAPI コアの起動、停止、再起動、状態更新。
- インストール状態、実行状態、プロセス ID、待受ポートの確認。
- OpenAI・Claude・Gemini 互換のエンドポイントをすぐにコピー。
- ローカル接続状況とアプリ/コアのバージョンを一目で確認。

コアのインストール、バージョン比較、オフラインインストールは**バージョン管理**ページから行えます。

### OAuth アカウント認可

「アカウント」ページでは、対応する各プロバイダーのブラウザ認可フローを一元管理し、認可済みの認証情報を
1 つのフラットな表にまとめて表示します。クォータ、有効期限、優先度もひと目で確認できます。

- Codex OAuth
- Claude OAuth
- Antigravity OAuth
- Kimi OAuth
- xAI OAuth

EvelProxyTool はブラウザで認可ページを開き、自動リダイレクトが利用できない場合はコールバックを手動で
完了する操作にも対応しています。クォータの自動定期更新もオプションで設定できます。

### API プロバイダーの集約

プロバイダー管理画面では、プロトコルまたはプロバイダーごとにアップストリームの API 認証情報とエンドポイントを
管理できます。

- Codex
- OpenAI 互換プロバイダー
- DeepSeek
- Claude
- Gemini

複数の接続を追加したり、既存のエントリを検索したり、プロバイダーの状態を更新したりでき、統一されたローカル
CLIProxyAPI エンドポイント経由でそれらを利用できます。リクエストとレスポンスは、対応する OpenAI・Claude・
Gemini および互換フォーマット間で変換できます。

### 利用履歴とトークン分析

「利用状況」ページでは、ローカルのリクエスト状況とトークン消費量を把握できます。

- リクエスト総数、トークン数、成功率、スループット、キャッシュヒット率、推定コストを確認。
- 時間、モデル、プロバイダー、ソース、キー、結果でフィルタリング。
- リクエスト/トークンの推移、入力・出力・推論・キャッシュ利用状況を確認。
- リクエスト詳細、分析ビュー、価格統計を閲覧。
- CPA のリアルタイム利用状況サブスクリプションを通じて、堅牢なローカル受信ボックスと自動 HTTP フォールバックで収集。
- 起動時に一度だけ旧バージョンの利用状況データベースをアップグレードし、`usage-records/backups` にバックアップを保存。

### エージェントクライアント設定

「エージェント設定」ページは、インストール済みのデスクトップ/CLI クライアントを検出し、ローカルプロキシへの
接続を支援します。対応クライアントは以下のとおりです。

- Claude Code
- Claude Desktop
- Codex
- OpenCode
- OpenClaw
- Hermes Agent
- Pi（CLIProxyAPI プロバイダー拡張と併用）
- ZCode
- Kimi Code
- Grok Build

対応クライアントについては、利用可能なモデルカタログの同期、デフォルトモデルの選択、管理設定を適用する前の
元の設定のバックアップ、以前の設定への復元が行えます。

## その他の機能

- コア設定、API キー、リモート管理用の認証情報、ルーティング戦略を管理。
- クライアントに表示されるモデルエイリアスを作成し、プロバイダーモデルや推論レベルに割り当て。
- 認証ファイルのアップロード、ダウンロード、確認、管理。
- プロバイダーのクォータとアカウントの利用可否を確認。
- macOS のメニューバーや Windows のシステムトレイに常駐可能。
- ベトナム語、英語、簡体字中国語、日本語のインターフェースに対応。

## クイックスタート

1. [GitHub Releases](https://github.com/evel2903/EvelProxyTool/releases/latest) からお使いの OS 用パッケージをダウンロードします。
2. Windows または Linux のアーカイブを展開するか、macOS の DMG を開きます。
3. EvelProxyTool を起動します。
4. **バージョン管理**を開き、同梱または最新版の CLIProxyAPI コアをインストールします。
5. **ホーム**に戻ってコアを起動し、必要なローカルエンドポイントをコピーするか、OAuth/API プロバイダーを設定します。

## アップグレード

各 Windows リリースでは、完全版 ZIP とレガシー用の `update` ZIP の両方が公開されます。これにより、
まだ移行していない古いクライアントでもアプリ内更新を利用でき、新しいクライアントは同梱コアも更新できる
完全版パッケージを使用します。

現在の Windows・Linux・macOS のリリースパッケージはアプリ内自動更新に対応しています。Linux は実行時データを
維持したままポータブルアプリケーションファイルを置き換え、macOS は署名済みのアプリケーションバンドルを
置き換えます。各プラットフォームは新バージョンの起動成功を確認してから完了とし、起動に失敗した場合は
自動的にロールバックします。インストールディレクトリは現在のユーザーが書き込み可能である必要があります。

既存の Linux・macOS 環境では、クロスプラットフォーム自動更新マーカーを含むリリースへの手動アップグレードが
1 回必要です。そのリリースを一度起動すれば、以降はアプリ内更新が利用できます。

v0.2.5 以前をお使いの場合は、以下の手動移行を一度行ってください。EvelProxyTool を終了し、お使いのアーキテクチャ
向けの最新の完全版 Windows ZIP をダウンロードし、そのトップレベルディレクトリの内容を既存のインストール
ディレクトリに上書きコピーします。既存のディレクトリを先に削除しないでください。`config.toml`、`oauth`、
`cpa-core/config.yaml` などのユーザーデータはそのまま残ります。新バージョンを起動した後は、以降のリリースで
アプリ内自動更新が利用できます。

## 対応プラットフォーム

GitHub Actions は以下のリリースパッケージをビルドします。

| OS | アーキテクチャ | パッケージ |
| --- | --- | --- |
| Windows | amd64、aarch64 | ZIP |
| macOS | amd64、aarch64 | DMG |
| Linux | amd64、aarch64 | TAR.GZ |
